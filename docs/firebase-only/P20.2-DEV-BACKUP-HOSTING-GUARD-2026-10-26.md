## Vấn đề gốc và sửa tối thiểu

**Root cause 1:** `.firebaserc` root mặc định vẫn chứa ID PROD, dễ nhầm project nếu chạy `firebase deploy` không chỉ rõ đích.

**Fix:** Thêm `firebase.dev-backup.json` chỉ chứa Hosting, `site=hnl-qltc-dev-backup`, và `scripts/dev-backup-hosting.mjs`. Mọi deploy dùng **đồng thời** project ID và file cấu hình độc lập, `--only hosting` và `--non-interactive`. Không đụng `.firebaserc`/`firebase.json`/Rules gốc.

**Root cause 2:** Lệnh `npm run build` tạo cả `dist/index.html` (Vite web) và `dist/server.cjs` kèm sourcemap; nếu dùng toàn bộ `dist` làm Firebase Hosting public thì có thể phát tán server bundle / sourcemap.

**Fix:** Stage CHỈ tài nguyên web có định dạng cho phép vào `dist-dev-backup-hosting`, loại `.cjs`, `.map`, PEM, source TS, file ẩn, installer EXE/APK, symlinks. Manifest ghi SHA256 từng file và hash cấu hình DEV backup. `.gitignore` bỏ qua staging.

**Root cause 3:** Build sai môi trường có thể trỏ sang DEV chính hoặc PROD. Script yêu cầu `.env.local` có marker quản lý `backup`, trùng tuyệt đối `.env.dev-backup.local`, project ID + App ID + sender ID chính xác, URL R2 trống, trusted writer OFF, AI OFF; từ chối env production và kiểm tra bundle JS chứa chính App ID/API key DEV backup.

## Quy trình hoàn tất trên máy/CI có npm và quyền Firebase CLI

**Chỉ làm khi có npm registry, kiểm tra Rules và phê duyệt triển khai DEV backup.**

```bash
# Sao chép từ cấu hình public SDK mẫu, không đưa secret vào GitHub
cp .env.dev-backup.example .env.dev-backup.local
node scripts/dev-firebase-switch.mjs backup
node scripts/dev-backup-hosting.mjs check
npm ci
npm run typecheck
npm run lint
node scripts/dev-backup-hosting.mjs build
node scripts/dev-backup-hosting.mjs deploy-hosting --confirm-backup-only
```

Lệnh cuối cần Firebase CLI đã đăng nhập đúng tài khoản có quyền **trên project backup**, deploy riêng Hosting bằng config tách biệt. Nó **không triển khai Rules, Cloud Functions, Storage, PROD, hay DEV chính**. CLI cần được kiểm tra/đăng nhập trước; không dùng `firebase deploy` trần.

> CHÚ Ý: Nếu bật dự phòng cùng lúc với DEV chính, dữ liệu hai Firestore là **hai cơ sở độc lập**. Không có đồng bộ hai chiều, không thể đơn giản “quay về” rồi thấy đủ thay đổi tại backup. Trước khi chuyển ngược về DEV chính phải đối chiếu và có phương án xuất/nhập an toàn, giữ ID/owner/ảnh và khả năng rollback. Không bật tự động switch giữa phiên đăng nhập.
